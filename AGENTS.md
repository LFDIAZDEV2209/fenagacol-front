# Fenagacol front — agent notes

Next 16.3 / React 19 / Tailwind 4 / Supabase. Public mobile-first `/registro` (4-step wizard) + session-gated `/dashboard` (desktop-first). UI copy in Spanish, keep it simple (campesino audience).

## Commands (Yarn 4 + PnP — use `yarn`, not npm)

- `yarn dev` / `yarn build` / `yarn start` / `yarn lint`. No test or typecheck scripts exist — verify with `yarn build` + `yarn lint`.
- Keep the `--webpack` flag on `dev`/`build` (default bundler differs in Next 16).
- Path alias `@/*` maps to repo root (`./*`). Strict TS, `moduleResolution: bundler`.
- No CI workflows, no test framework. `README.md`'s npm commands are stale; `package.json` (`yarn@4.18.0`, `.pnp.cjs`) is truth.

## Env and secrets

- Copy `.env.example` → `.env.local` (gitignored via `.env*`). Also set vars in Vercel Project Settings before deploy.
- Required: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
- `SUPABASE_*` service key and `ADMIN_*` are server-only — never add `NEXT_PUBLIC_` prefix, never import them into client components.

## Auth (custom cookie, NOT Supabase Auth)

- Session = HMAC-signed httpOnly cookie `fenagacol_session`, 7-day TTL (`lib/session.ts`). Credentials only from `ADMIN_EMAIL`/`ADMIN_PASSWORD`.
- Route gate is `proxy.ts` (Next 16 convention — there is no `middleware.ts`; don't create one). Matches `/dashboard/:path*` + `/login`; `/login` honors `?next=`.
- Admin APIs (`app/api/admin/*`) guard with `requireAdmin()` from `app/api/admin/_lib.ts` → 401 JSON when unauthenticated. Auth endpoints: `/api/auth/login|logout|me`.

## Data: Supabase-first with local fallback

- Source order: Supabase → `localStorage` cache (key `fenagacol_cfg_v1`) → `lib/mock-data.ts`. App must keep working offline/401 (public form gets silent 401 on admin endpoints by design).
- Public anon (RLS) may only SELECT `roles`/`associations` and INSERT `people`/`person_roles` (`lib/supabase/queries.ts`). Writes use `return=minimal` + client-generated UUID.
- Dashboard never queries Supabase directly: use hooks in `lib/server-data.ts` (`usePeopleQuery`, `useSummaryQuery`, `fetchExportRows`) hitting `/api/admin/directory|summary|export`. Requests are debounced (~350ms) + AbortController-cancelled; preserve that pattern.
- `lib/supabase/server.ts` (incl. `createServiceClient`) is server-only (`next/headers`). Client code uses `lib/supabase/client.ts` only.
- `createRegistration` error codes callers must handle: `DUPLICATE_IDENTITY` (unique `identity_number`), `STALE_ROLES` / `STALE_ASSOC` (catalog changed), `NETWORK` (config-store falls back to local save).

## Domain invariants (DIVIPOLA + dynamic catalogs)

- Department `id` = 2-digit DIVIPOLA; municipality `id` = 5-digit with `departmentId` FK. Filter `MUNICIPALITIES` by `departmentId` — never hardcode dept→muni maps in components.
- Roles/associations are admin-editable server data, not constants. Match roles by label (case-insensitive); resolve assoc names via `resolveAssocName(id, assocs)` in `lib/config-store.tsx`, never the static list directly.
- Search sanitization + filter clamping live in `app/api/admin/_lib.ts` (`cleanSearch`, `parseFilters`, pageSize ≤ 100, export cap 20k rows) — extend there, don't reimplement per route.

## UI structure

- `app/`: `registro/` (public wizard), `login/`, `dashboard/`, `api/`. `components/`: `registro-form.tsx`, `filters-bar.tsx`, `dashboard-charts.tsx`, `person-detail.tsx`, `share-form.tsx`, `ui.tsx` (hand-rolled primitives — no shadcn/radix deps installed), `toast.tsx`, `site-header.tsx`.
- Global providers (order matters) in `app/layout.tsx`: `ToastProvider` → `ConfigProvider` → `AuthProvider`. Font Manrope, `lang="es"`.
- `/registro` rules: one step visible at a time with progress, validate before advancing, preserve values on back, sticky bottom nav, large touch targets, no tech jargon.
